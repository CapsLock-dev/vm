# Gm

Gigachad machine

## Состав

| Каталог   | Что внутри                                                        |
|-----------|-------------------------------------------------------------------|
| `common/` | Общие заголовки: `sv.h` (String_View), `container.h` (динамический массив и очередь), `logger.h` (логи) |
| `gm/`     | Gigachad machine(виртуальная машина). `gm.c` — ядро, `gme.c` — CLI-приложение - эмулятор виртуальной машины(он же по сути интерпретатор), `opcodes.h` — коды операций и таблица инструкций ассемблера |
| `gasm/`   | Ассемблер: `compiler.c` — парсер и генератор байт-кода, `gasm.c` —  CLI-приложение - парсит .gasm в бинарный файл для интерпретатора `gme`|
| `examples/` | Пример программы на `.gasm`. Считает сумму чисел от 0 до 10 и выводит на экран.|

Главные файлы(точки входа): `gm/gme.c` и `gasm/gasm.c`.

## Сборка и запуск

```sh
./build.sh                                  # build/gasm, build/gme
./build/gasm examples/sum.gasm -o sum.gm    # по умолчанию пишет a.gm
./build/gme sum.gm
```

Требуется gcc и POSIX `getline`. Флаги сборки: `-ggdb -Wall -Wextra`,
include-пути `-Icommon -Igm`;

## Устройство VM

- 256 регистров (`REG_COUNT`), регистр — `Value`.
- `Value` — динамический тег + union: `TAG_INT` (`int64_t`), `TAG_DOUBLE`
  (`double`), `TAG_NIL`. Арифметика: int `(+-*/)` int остаётся int (с проверкой
  переполнения), любая пара с double — double.
- `Vm` хранит код (`code`, `code_len`), `ip` и `status`. Исполнение —
  `vm_execute_step()` (одна инструкция) в цикле `execute_program()`.
- `ip` — индекс в массиве байт. Все мультибайтные операнды читаются
  little-endian; чтение за границей кода даёт `VM_FAULT_OOB`.
- Ошибки не роняют процесс: VM выставляет `VmStatus` (см. `vm_get_status()`),
  цикл останавливается, раннер возвращает ненулевой код.
- Прыжки (`jmp`, `jz`) — относительные, смещение считается **от байта после
  инструкции** и хранится как `int32_t`. Выход за границы кода — `VM_FAULT_BAD_IP`.

## Формат инструкции

Все инструкции: 1 байт опкода + операнды.

| Опкод | Мнемоника | Кодировка                          |
|-------|-----------|------------------------------------|
| 0     | `nop`     | —                                  |
| 1     | `halt`    | —                                  |
| 2     | `load`    | `u8 dst, i32`(загружает 4-байт int)|
| 3     | `load`    | `u8 dst, u64`(загружает 8-байт double)|
| 4     | `mov`     | `u8 dst, u8 src`                   |
| 5–8   | `add/sub/mul/div` | `u8 dst, u8 a, u8 b`       |
| 9     | `cmp_lt`  | `u8 dst, u8 a, u8 b` (результат 0 - false/1 - true) |
| 10    | `jmp`     | `i32 offset`                       |
| 12    | `jz`      | `u8 reg, i32 offset`               |
| 13    | `print`   | `u8 src`                           |

`load` различает int и double по типу литерала: int кодируется как `int32`
(значения вне диапазона — ошибка ассемблера), double — как 8 байт IEEE-754.

## Ассемблер

Синтаксис: одна инструкция на строку, операнды через запятую, регистры
`r0..r255`. Строки команд и сигнатуры операндов задаются таблицей
`instructions[]` в `gm/opcodes.h` (`r` — регистр, `i` — int, `f` — float,
`n` — int или float). Чтобы добавить мнемонику, достаточно добавить строку в
эту таблицу и обработчик в `emit_instr()` (`gasm/compiler.c`).

Парсер (`parse_line`) проверяет структуру строки и типы операндов, возвращая
`ParseError` с номером колонки; `error_message()` печатает диагностику в
формате `file:line:col`. Кодогенерация — набор `emit_*()`-функций, каждая
пишет опкод и операнды в выходной файл.

## Известные ограничения и баги

### Баги, которые уже воспроизводятся

- **`nop` эмитится как `halt`.** В `emit_instr` у `OP_NOP` и `OP_HALT` общий
  `case`. Сейчас недостижимо (мнемоники `nop` нет в таблице), но при её
  добавлении поведение будет неверным.(как будто норм)
- **NaN считается истиной.** `check_reg_cond` делает `v.as.f != 0.0`, а
  `NaN != 0.0` истинно.(вроде я проверяю невалидные операции, так что NaN даже не получится)

### Чего ещё нет

- В таблице `instructions[]` только `halt, load, cmp_lt, jz, add, jmp, print`.
  `sub/mul/div/mov/nop` есть в VM и `Opcode`, но недоступны из ассемблера;
  `OP_JMP_IF` (`jnz`) вообще не имеет мнемоники.

Докоммичу, лень было
- Нет меток, директив, комментариев (`;`/`#`), секций. Прыжки задаются вручную
  относительным смещением от следующей инструкции (см. `examples/sum.gasm`).

Следующий коммит будет улучшением ассемблера
- Нет стека вызовов, памяти/кучи, массивов, строк и ввода. Программа умеет
  только регистры, арифметику, сравнение, переходы и `print`.

Это будет, но не сразу
- Нет заголовка файла: ни магии, ни версии, ни длины, ни контрольной суммы.
  `gme` исполняет любые байты, пока не упрётся в ошибку; нет дизассемблера и
  валидатора байткода.

Пока нерелевантно
- Нет неявного `halt`: программа без `halt` в конце дочитывает код и падает в
  `VM_FAULT_OOB` уже после выполнения полезной части.

Придумаю что-нибудь
- Нет тестов, CI, make/cmake. `build.sh` не использует `-Werror`, не умеет
  `clean` и пересобирает всё всегда.

Надо будет обсудить систему сборки, тесты нерелевантны сейчас

## Магические числа и константы

«Голые» числа, смысл которых не виден из кода. При изменении формата сначала
обновляйте этот раздел(окей, дипсик).

- **`REG_COUNT = 256`** (`gm/opcodes.h`) — число регистров. Номер
  регистра кодируется одним байтом, поэтому 256 — это ровно весь диапазон
  `r0..r255`. Больше без расширения операнда не сделать, меньше — можно, но
  часть байтов станет невалидной. Константа продублирована в двух
  заголовках — держите их синхронно.(Факт)
- **Числа опкодов 0–13** (`Opcode` в `gm/opcodes.h`) — это формат файла, а не
  просто enum. Менять значения/порядок нельзя, не сломав уже собранные `.gm`;
  новые опкоды добавляйте только в конец. (Ну тут факт)
- **Ширины операндов 1 / 4 / 8 байт** (`gm.c`, `compiler.c`) — 1 байт на опкод
  и номер регистра, 4 байта на `int32` (литерал `load` и смещение прыжка),
  8 байт на биты `double`. Все многобайтные числа little-endian; порядок
  байт — часть формата.(База)
- **`INT32_MIN..INT32_MAX`** — предел целочисленного литерала `load` и
  смещения прыжка. Ассемблер отвергает литералы вне диапазона
  (`Cannot emit instruction`), хотя `Value` хранит `int64_t`.(Надо будет обсудить этот моментик)
- **Коды возврата** — 0 успех, 1 любая ошибка.(Посмотрим)
- **ANSI-цвета 160 / 204 / 3 / 12** (`common/logger.h`) — индексы 256-цветной
  палитры для error/bug/warning/info; чисто косметика.(Да)
- **Теги `Value` 0/1/2** — `TAG_INT`, `TAG_DOUBLE`, `TAG_NIL`. В файл не
  пишутся, но `Vm vm = {0}` делает все регистры `TAG_INT` со значением 0, а
  не `nil`.(Некритично)
